## Failure-path gate — 2026-10-15, before mutation

Source finding: Plugin.Fail disables Enabled, while Completion, repetition guards and entry/UI paths consult Enabled and science-reserve settlement does not. Consequently an already-started native job can reach OnFinishedCraft after presentation failure without its formula grant. Disabled CraftReally/EnqueueCraft guards currently fall through, so existing registered jobs are not independently protected against new payment. This is a statically established path risk, not a reported installed loss.

Chosen boundary: reject new registered research starts/queues after disabling; retain registry-verified completion and paid-work single-operation/refund settlement independently of optional presentation. No automatic Cancel, world scan, fee refund on a mere UI error or global unpatching. Full unpatching would discard necessary settlement hooks; forcibly cancelling work would introduce a new interruption/payment policy. Retaining the narrow existing native completion/cancel/removal paths is the smallest mechanism preserving the adopted outcome.
